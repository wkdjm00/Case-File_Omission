노션 「《사건기록: 누락》 기획 정리본」의 2026-11-13 추가 내용(임시 UI·임시 3D 게임보드로 전체 기능을 실제 조작·테스트할 수 있는 상태, 09 TEMP_LAYOUT_V1, 사건보드 계약, 시간 보내기)을 Unity에 반영한 기록이다.

## 실행 방법

1. Unity에서 `Assets/01_Scenes/P0_Playtest.unity`를 연다. (씬이 없거나 다시 만들려면 메뉴 **Case File > P0 테스트 씬 만들기**)
2. Play → 타이틀에서 시드 입력(기본 7) → **새 테스트 세션 시작**.
3. 같은 시드는 같은 의뢰를 만든다(고정 테스트 사건 역할). 의뢰는 기존 생성 파이프라인이 만든 것이며, 손으로 쓴 fixture가 아니다.

### 원문에 없어 구현하지 않은 것 (사용자 결정 필요)

- **추론 생성 단서(4-2) — 사용자 결정(2026-11-13): 별도 구현하지 않는다.** "어디에 어떤 단서가 있을 것 같다"를 따로 입력받는 방식은 필요 없는 단계라는 판단. 보고서를 읽고 모순을 분석하는 추론은 의뢰 보고서 핵심 문장 → 완료 시 후속 조사 방향 공개 흐름이 맡는다(이미 구현). 노션 4-2 문구는 이 결정에 맞게 정리가 필요하다.
- **부수 범죄 — 구현함**: 발생 여부를 먼저 **30%**로 판정(사용자 확정 2026-11-13, 구현 명세 4.7의 20%를 대체)하고, 연결 조건·시점은 `Docs/의뢰사건_랜덤생성_구현명세.md` 4.7을 따른다. 발생하면 → 연결 조건을 만족하는 후보만 확정 가중치로 선택 → 핵심 사건 10~30분 뒤 시간표 사건으로 추가(연결 이유·인물 기록) → 그 방에 흔적 자료(E12) → 보고서 '부수 범죄' 문단(`SubCrimeGenerator`). 절도·협박·폭행 후보만 쓴다. 살인(목격자 사망)·실종 관련(시신 이동) 후보는 목격 증언·시신 위치를 전제로 한 자료 생성과 충돌해 아직 뺐다.
- **NPC·경찰이 회의 차례에 어떤 카드를 내는지**: "보유 카드만 제시하거나 넘길 수 있다"만 있고 선택 규칙이 없어 넘긴다.
- **엿듣기 목격 시 경찰 의심도**: 수치 없음.
- **조합 확장 — 구현함(4차)**: 시간표 생성기에 **피해자 자발적 이탈**(핵심 사건 뒤 현관 홀로 스스로 떠남, 이후 일정 없음)과 **시신 은닉**(CONCEAL-04, ACT-SUB-MUR-04, 시신을 판에 두지 않고 숨긴 물건을 조사해야 발견)을 추가했다. 이제 폭행→실종, 실종→폭행, 실종→협박, 살인→협박(이탈·은신)과 실종·절도·협박→살인(시신 은닉)이 생성된다. 이탈 사건에는 현관 물품 상태·떠나는 모습 목격 진술·자필 메모가, 각 조합에는 경찰이 몰랐던 사실(사망·부상·은신 이유)이 붙는다(`ContractGenerator.RequiresVictimDeparture/RequiresHiddenBody`, `ContractTimelineGenerator`, `CaseDetailGenerator`).
- **조건부 조합 14개 전부 생성(5차)**:
  - 폭행→살인: 공격받은 피해자가 이웃 방으로 옮겨 가 늦게 숨짐(ACT-SUB-MUR-02, `DelayedDeath`). 시신은 숨진 방, 공격 방에서 핏방울이 이어지고, 경찰은 인계 시점에 사망을 모름.
  - 절도→실종: 가해자의 유인·강제 이동으로 물건 주인이 실종되고 물건은 주인과 함께 사라짐. 서재에 '본인이 직접 꺼내 감' 반출 기록. 원문 조건("타인의 실제 절도 없음")에 따라 이 조합에는 부수 절도를 붙이지 않는다.
  - 생성 불가 6개(04 §6)는 그대로 막는다. 테스트 `AllFourteenConditionalCombinations_AreSupported`로 고정.
- 폭행 ASS-02(반복 공격)는 아직 없다.
- **AI 실제 제공자**(URL·키): 배포 환경 설정 사항. 사건 생성 단계(CORE_TRUTH·CASE_MATERIALS·REPORT_TEXT)는 아직 결정적 생성기만 쓴다.

## 기획과 어긋나 남은 것 (구현 차단은 아님, 확인 필요)

1. **시간 단위**: 09는 15분 단위 시간 보내기·대화 30분이지만 `GameStateController`는 구간당 12칸(1칸=1시간). 시간 보내기는 칸 단위로 넣었다.
2. **회의 결론 투표**: 노션 최신은 "개인 의견 점수 50 초과 찬성"이지만 `GameSession.ProposeConclusion`의 기본 투표는 아직 "참가자의 플레이어 의심도 35 미만이면 찬성"(임시)이다. 개인 의견 점수 계산(06 2026-11-11)은 아직 코드에 없다.
3. **의뢰 보고서 방식**: 노션 최신(V-13)은 자연어 핵심 문장 + 정확성·증거 충분성 검증이지만 코드는 항목별 단서 연결 방식이다. UI는 현재 코드 방식대로 만들었다.
4. **대체 카드 묶음이 빈 상태의 은폐**: 09는 "묶음이 비면 손패가 5장보다 적어질 수 있다"고만 한다. 조작 기록이 대체 단서를 필수로 요구해 지금은 묶음이 비면 은폐를 막는다.
5. **총기**: 노션 V-15에 따라 사격 UI는 넣지 않았다(`GameSession.FireAt`은 있음).
6. **NPC 자기 차례**: 원문에 판단 규칙이 없어 NPC·경찰 차례는 넘어간다(기존 임시).
7. **빌드**: 머티리얼을 `Shader.Find("Universal Render Pipeline/Lit")`로 만든다. 독립 실행 빌드에서는 셰이더가 빠질 수 있어 빌드 전 확인이 필요하다(에디터 플레이는 문제없음).
